# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файл из `migrations/0001_create_tasks.up.sql` монтируется в `docker-entrypoint-initdb.d` и применяется только при инициализации пустого data volume.

## Swagger

Swagger UI:

```text
http://localhost:8080/swagger/
```

OpenAPI JSON:

```text
http://localhost:8080/swagger/openapi.json
```

## API

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`

## Изменения для тестового задания

Для выполнения тестового задания я создал таблицу periodicities, в которой для каждой периодичной задачи задаю необходимое правила в соответствующие поля. В моей системе периодичные задачи не пересоздаются, а просто обновляют статус - благодаря этому крон, ответственный за обновление статусов задач, не плодит их. В случае необходимости видеть историю задач, то в будущем можно будет добавить отдельную таблицу для логов.

Проблему с ежемесячными задачами, при которой определённых дней может не быть в каких-то месяцах (с 29 по 31) я решил через дополнительную проверку подобных задач первого числа нового месяца. Мне кажется это довольно логичное решение, хотя с пользовательской точки зрения не совсем учитывает кейс когда нам нужно чтоб задача ТОЧНО появилась именно в последний день месяца. Для подобного поведения выгоднее использовать периодичную задачу с конкретными датами - и выставить их на год вперёд.

Вышеописанный крон срабатывает дважды - в полночь и при старте API. Для данного тестового задания я опустил возможность использования системы врачами с разными часовыми поясами, но в принципе она реализуется просто - имеющийся крон должен срабатывать ежечасно и должен иметься какой-то источник часовых поясов, допустим, в таблице с мед. учреждениями.
